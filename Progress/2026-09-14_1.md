## Decisions / Tradeoffs

- No new ROI restriction, object tracking, or duplicate manual-review workflow was added in this change.
- The normal detector confidence remains the baseline/strong helmet threshold. `strong_helmet_confidence` is derived internally and is not another CLI setting.
- The lower helmet floor retains weak helmet boxes for final verification only. It does not lower thresholds for other detector classes.
- CLI arguments override JSON configuration. Explicit `--label-conf helmet=...` remains authoritative over the automatic helmet floor.
- A run that intentionally needs every effective threshold at `0.45` should pass both `--conf 0.45` and `--helmet-alert-confidence 0.45`, with conflicting per-label overrides removed.
- Weak helmet evidence suppresses `NO_HELMET` only when every current candidate person has associated verification-level evidence at the alert boundary.
- Source credentials are redacted before new artifacts are persisted, but existing legacy artifacts are not migrated or deleted by this change.
- The current production-oriented `roll_sop_v1` path is the target of this experiment. The reviewed operator-profile interaction remains deferred.
- No dependencies, lockfiles, model files, ROI files, deployment services, or live AI-box state were changed.
